# عزل بيانات الحساب بعد التبديل (خصوصية — نموذج جوجل)

> **الحالة:** إلزامي لكل منتج مرتبط بـ `id.bhd-om.com`.  
> **تاريخ التحليل:** 29 أكتوبر 2026 — عطل مؤكد على [BHD-HR](https://github.com/ainoamn/BHD-HR).  
> **لوحة الربط:** https://id.bhd-om.com/admin#connect  
> **النموذج:** مثل جوجل `authuser` — كل تبويب مربوط بحساب عبر `?au=<sub>`.

---

## العَرَض

يتغيّر الحساب في قائمة التبديل، لكن واجهة المنتج تبقى للحساب السابق، أو تبويبان لنفس المنتج يتزامنان عند التبديل.

---

## السبب الجذري

1. تبديل Bearer بدون إعادة كتابة ربط المنتج (`ain_bhd_sub` / جلسة محلية).
2. كوكي الهوية مشترك بين التبويبات.
3. غياب ربط URL بالحساب (`?au=`) → لا عزل حقيقي بين النوافذ.

---

## القاعدة (نموذج جوجل)

### ربط التبويب (`?au=<sub>`)
1. بعد التبديل: `?au=<bhdSub>&_bhd=<ts>` مرة واحدة ثم يُزال `_bhd` بهدوء.
2. `sessionStorage`: `bhd_account_tokens[sub]` + `bhd_active_au`.
3. عند التطابق: لا ملاحظة ولا حجاب.
4. عند الانحراف: `POST /api/auth/bhd/rebind` JSON صامت.

### التبديل (اختيار حساب)
1. غطاء فارغ بلا نص.
2. `POST /api/auth/switch` مع `X-BHD-Persist-Cookie: 1`.
3. form `rebind` لإعادة تحميل كاملة.

### نوافذ متعددة
`BhdSilentSso` كل ~20ث أو عند الظهور — بلا وميض.

مرجع التطبيق: `src/lib/identity/client.ts` + `BhdPrivacyGate` + `BhdSilentSso` في `_app.tsx`.

---

## تحقق

1. حسابان → بدّل → الرابط فيه `au=` → البيانات للحساب الجديد فقط.
2. تبويبان بـ `au` مختلف → لا خلط بعد rebind صامت.
